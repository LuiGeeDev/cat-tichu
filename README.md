# 고양이 티츄 🐾

고양이 얼굴 카드로 즐기는 **4인 온라인 티츄(Tichu)**. 친구 셋을 초대해 두 팀으로 나누어
Fata Morgana 공식 4인 룰로 겨루는 웹 게임입니다. UI는 전부 한국어입니다.

- 초대 코드/링크로만 입장 (관전·채팅 없음), 로비에서 목표 점수 선택
- **3명 + 봇 1명** 플레이 가능 (봇은 손패 강도·조합 비용을 고려해 자동 플레이)
- 서버가 모든 판정을 담당하는 authoritative 구조 (상대 손패·먹은 카드는 절대 노출되지 않음)
- 내가 가져간 트릭 카드와 점수는 언제든 확인 가능
- 티츄와 그랜드 티츄는 한 라운드에 하나만 선언 가능
- 끊김/새로고침 후에도 같은 자리로 자동 복구
- 데스크톱·모바일 반응형

## 빠르게 실행하기

```bash
npm install
npm run dev        # 서버(8787) + Vite(5173) 동시 실행
```

브라우저에서 <http://localhost:5173> 접속 → 닉네임 입력 → **새 방 만들기**.
친구에게 초대 링크(`http://localhost:5173/#/room/코드`)를 보내면 됩니다.

프로덕션 모드(단일 포트):

```bash
npm run serve      # vite build 후 node server/index.js (http://localhost:8787)
```

## 실제 배포 주소

**https://cat-tichu.onrender.com** (Render 무료 플랜, `main` 브랜치 자동 배포)

- 소스: <https://github.com/LuiGeeDev/cat-tichu>
- `render.yaml` 블루프린트로 Docker 서비스를 생성합니다.
- 무료 플랜은 15분간 트래픽이 없으면 슬립하므로, 오랜만에 열면 첫 로딩에 약 1분이 걸릴 수 있습니다.
  게임 중에는 하트비트 트래픽이 있어 슬립하지 않습니다.
- 배포 상태: `GET https://cat-tichu.onrender.com/healthz`

## 직접 배포하기

이미지 하나로 프론트엔드와 WebSocket 서버가 함께 뜹니다.

```bash
docker build -t cat-tichu .
docker run -p 8787:8787 cat-tichu
```

- `PORT` 환경변수로 포트를 바꿀 수 있습니다 (기본 8787).
- HTTPS 뒤에 두면 클라이언트가 자동으로 `wss://`를 사용합니다.
- 헬스 체크: `GET /healthz`
- 방 상태는 메모리에 저장되므로 **단일 인스턴스**로 운영해야 합니다. 여러 대로 늘리려면
  Redis 같은 공유 저장소와 WebSocket sticky session이 필요합니다.
- Railway / Render / Fly.io / Google Cloud Run 등 컨테이너 배포를 지원하는 곳이면 어디든
  올릴 수 있습니다. (Cloud Run은 WebSocket 타임아웃 설정을 확인하세요.)

## 게임 흐름

1. 방장이 방을 만들고 초대 링크를 공유합니다. 로비에서 **목표 점수**(500 / 1,000 / 1,500 / 2,000점)를 정할 수 있습니다.
2. 세 명이 모이면 방장이 **봇으로 채우기**를 누르거나, 네 명이 모이면 바로 **게임 시작**.
3. 각자 8장을 받고 그랜드 티츄를 선언할 수 있습니다. 모두 **준비**를 누르면 6장을 더 받습니다.
4. 14장 중 3장을 골라 왼쪽 상대 · 파트너 · 오른쪽 상대에게 한 장씩 건넵니다.
5. 참새를 가진 사람이 선으로 시작합니다. 라운드가 끝나면 점수를 계산하고 방장이 다음 라운드를 시작합니다.
6. 먼저 목표 점수에 도달한 팀이 승리합니다.

내가 가져간 트릭 카드와 점수는 화면 아래 **내 정보 영역**(고양이·닉네임)을 누르면 볼 수 있습니다.
다른 플레이어의 카드는 공개되지 않고 장수와 점수만 표시됩니다.

팀은 마주 앉은 두 명(`0·2`번 자리 vs `1·3`번 자리)이고, 진행 방향은 시계 방향입니다.

## 구현된 규칙

공식 룰(<https://fatamorgana.ch/fatamorgana/tichu/english-rules>)을 기준으로 구현했습니다.

- **카드**: 옥·검·탑·별 4무늬 × 2~A + 참새·개·봉황·용 = 56장. 10은 9와 J 사이.
- **조합**: 싱글, 페어, 트리플, 풀하우스, 스트레이트(5장 이상), 연속 페어(2쌍 이상),
  폭탄(같은 숫자 4장 / 같은 무늬 5장 이상 연속).
- **참새**: 1로 취급, 스트레이트에 포함 가능. 낼 때 2~A 소원 가능. 소원은 이행될 때까지 유지되며,
  소원 카드를 가지고 있으면서 낼 수 있는 사람은 반드시 이행해야 합니다(폭탄으로도 가능).
- **개**: 선으로만 낼 수 있고 파트너에게 선을 넘깁니다. 폭탄으로 막을 수 없습니다. 낸 직후 테이블에
  "개를 냈습니다 · 선이 ○○님에게 넘어갔습니다" 배너가 표시됩니다.
- **봉황**: 조합 안에서 2~A 와일드(폭탄 불가). 싱글로 낼 때는 앞 카드보다 0.5 높고, 선일 때는 1.5.
- **용**: 싱글 전용 최강 카드. 트릭을 이기면 상대 한 명에게 트릭을 넘깁니다.
- **티츄/그랜드 티츄**: 첫 카드를 내기 전 / 9번째 카드를 받기 전에 선언. 성공 ±100 / ±200.
- **점수**: 5=5점, 10·K=10점, 용 +25, 봉황 −25 (덱 합계 100점). 더블 승리는 200점으로 카드 점수 생략.
  마지막 남은 사람의 손패는 상대 팀에게, 그 사람이 모은 트릭은 1등에게 갑니다.
- **게임 종료**: 목표 점수 도달(기본 1,000점, 로비에서 변경 가능). 같은 라운드에 두 팀이 넘으면 점수가 높은 팀이 승리.

### 의도적으로 다르게 구현한 부분

- **폭탄은 자신의 차례에만 낼 수 있습니다.** 공식 룰은 차례가 아닐 때도 폭탄으로 끼어들 수 있지만,
  온라인 실시간 환경에서 동시 입력·우선순위 분쟁을 막기 위해 단순화했습니다.
  (규칙 모달과 이 문서에 명시)

## 구조

```
shared/tichu/       카드·조합·게임 엔진 (서버/클라이언트 공용, 순수 함수)
server/index.js     Express + ws 서버, 정적 파일 서빙, 하트비트, 정리 작업
server/rooms.js     방·좌석·초대 코드·재접속 토큰 관리
src/                React 19 클라이언트
  net.js            자동 재접속 WebSocket 클라이언트
  components/       홈·로비·게임·카드·규칙·모달
test/               엔진/조합 테스트 (node --test)
public/cats/        고양이 얼굴 이미지 (cat-1 ~ cat-7)
```

### 통신

- WebSocket 단일 경로 `/ws`. 클라이언트 → 서버: `create`, `join`, `action`, `ping`.
- 서버 → 클라이언트: `joined`, `state`, `error`, `info`, `left`, `pong`.
- 모든 상태 변경은 서버에서 검증하며, 플레이어별로 손패를 가린 `view`만 전송합니다.
- 같은 `actionId`의 중복 요청은 무시합니다.

### 안정성

- `localStorage`의 세션 토큰으로 새로고침·끊김 후 자동 재접속 (지수 백오프)
- 12초 앱 하트비트, 서버 25초 WebSocket ping, 30초 유휴 연결 정리
- 다른 탭으로 접속하면 기존 연결을 교체하고, 방은 6시간 동안 유지
- 네트워크 복구·탭 복귀 시 즉시 재연결 시도
